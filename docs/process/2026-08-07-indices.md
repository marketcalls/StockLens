# Index pages

**What was asked:** download every symbol and every index, and add index support
like screener.in — index pages listing constituents with returns and valuation,
plus index routes in the front end.

---

## The download

The symbol master and the index master were already loaded, but "already loaded"
is a claim about history, not about whether the code still works. So the sync ran
again for real:

| | |
| --- | --- |
| Companies | 5,630 |
| Indices | 239 |
| Index memberships | 23,367 |
| Index quotes | 229 |
| Index returns | 1,384 |
| Company quotes | 6,747 |

That is four API calls for the whole universe plus one for every company's price.

Fundamentals are the slow part: each company needs 59 calls, so the full set is
about 332,000 calls and eighteen hours. Rather than start eighteen hours of
traffic against someone else's API without saying so, this run is bounded at the
**top 500 companies** — roughly 29,500 calls and a hundred minutes — chosen by
index membership first and market cap second, so the names people actually search
for arrive first. The remaining companies keep their prices and market caps and
fill in their financials later.

## The pages

**`/indices`** lists all 239, grouped by category with broad-market first, and
opens with today's biggest index moves. There is a filter box and an NSE/BSE
switch, because 239 rows is too many to scan.

**`/index/NIF50`** is the detail page: level and day change, the exchange's own
valuation, returns across all eight horizons, medians across the constituents,
and the full member list sorted by any column.

Index membership on a company page used to be a row of inert grey chips. They are
now links, so you can go company → index → another company.

### The returns ladder

Eight horizons as bars either side of a shared zero line, rather than a column of
eight numbers.

The point is that the shape carries the meaning. The Nifty 50 is up 12.28% over
seven years and down 4.29% over six months — as numbers that is arithmetic you
have to do; as bars it is a long climb with a recent dip, read at a glance. Bars
scale against the largest return present rather than a fixed ceiling, so a set of
small returns still fills the space instead of collapsing into nothing.

A horizon the exchange did not publish is left out, not drawn as zero. Drawing it
flat would claim the index went nowhere.

## Three things the pages exposed

Opening the pages in a browser found three faults that no test would have caught,
because each one is a case of a number being *present but wrong in meaning*.

**INDIA VIX showed a P/E of 0.00.** A volatility index has no earnings, so it has
no earnings multiple. Upstream fills the valuation block with zeros where it does
not apply, and we stored them as measurements. Eight indices were affected — VIX,
the dividend-point series, the USD-denominated ones, and the inverse and leverage
series. A live index cannot trade at zero times earnings, so a zero there is an
absent figure. Now stored as absent and shown as a dash.

The dividend yield gets discarded only alongside P/E and P/B, never on its own: an
index of companies that pay no dividend really does yield 0%, and that is a
measurement worth keeping.

**Market cap showed 0.** The same problem in a different column, affecting 28
indices. No live index is worth nothing.

**The VIX page had an empty table.** A header row with nothing underneath, and a
note reading "medians across the 0 of 0 constituents". Both now say what is
actually going on: the exchange publishes a level for these series but not a
member list.

## Testing

371 backend tests and 72 front-end tests pass, up from 366 and 61.

The returns ladder has eleven of its own. One worth calling out checks that
horizons render shortest-to-longest **regardless of the order the object keys
arrive in** — the live API serialises them alphabetically, which puts 10Y first
and 1Y third. A component that trusted key order would have shown a plausible but
scrambled ladder, and it would have looked fine.

## On responsiveness

The tables hide columns at breakpoints and scroll inside their own box, the same
approach that fixed the statement table.

The containment is verified: squeezed to 360px the page does not scroll sideways,
and the 820px-wide table scrolls within its own 326px box. That was the failure
the statement table had.

The column-hiding itself is **not** verified by observation — this environment
would not let me change the browser viewport, and the breakpoints key off viewport
width. It is the same mechanism already proven on the statement table, but it has
been reasoned about rather than seen.
